本文档是《ERP MVP 设计文档 v1.5》的工程实施篇：将系统拆分为 12 个基础组件 + 11 个功能模块，定义契约接口、依赖矩阵、优先级（P0-P3）与三泳道并行开发计划。

1分层总览与拆分原则

拆分目的：基础组件先行（P0 一次建成、全局复用），功能模块按依赖分层并行开发，模块之间只通过契约接口通信，禁止横向直接读表——这是并发开发不打架的前提。

L0 基础组件层 C1 dbC2 authC3 rbacC4 errorC5 decimalC6 idempotencyC7 audit 横切基础设施，与业务无关。全部 P0，M1 前半段完成，是所有模块的地基。
L1 支撑组件层 C8 query 查询规范C9 notify 通知C12 file 文件 被多个业务模块共用的通用能力。P1，与基础数据模块同步开发。
L2 核心域层 M1 base 基础数据M2 stock 库存核心M3 price 计价引擎 被上层单据依赖的领域内核。base/stock 为 P0-P1；price 为 P1，可独立并行。
L3 业务单据层 M4 purchase 采购M5 sales 销售M6 process 配送发料M7 piece 报工计件 进销存与加工单据，仅依赖 L0-L2 契约。purchase/sales（P1）与 process/piece（P2）两条线并行。
L4 财务报表层 M8 bill 账单M9 payable 应付M10 report 报表M11 alert 预警C10 print 打印C11 schedule 定时 依赖业务单据数据落库后才有意义。P2-P3，最后集成。
三条铁律（并发开发的红线）：① 模块间禁止直接 import 别的模块的 Prisma model / repository，只允许调用其导出的 service 方法（契约）② 契约接口签名由本文档第 4 节定义，改动需评审同步所有泳道 ③ 前后端共享的类型/权限码/错误码放 packages/shared，双端从同一处 import。

2基础组件（C1-C12）

基础组件 = 与具体业务无关的可复用基础设施。每个组件独立目录、独立单测，一次建成全局复用。

编号组件优先级职责与对外接口验收标准
C1db 数据库P0PrismaClient 单例工厂；迁移脚本规范（SQL 迁移进 Git）；withTransaction(fn) 统一事务包装（含超时与重试 advisory lock）迁移可重复执行；事务包装单测通过
C2auth 认证P0登录（bcrypt、5 次锁 15 分钟）、JWT 签发/刷新（payload 含角色权限码）、token_version 失效、must_change_password 拦截中间件、refreshToken httpOnly Cookie旧 token 改密后失效；锁定与解锁正确
C3rbac 权限P0权限码常量 + 角色→权限映射（写死代码，来源 shared 包）；@RequirePermissions('sales:order:create') 装饰器 + 全局 Guard；多角色取并集矩阵全接口生效（对照 v1.3 §5.2）
C4error 错误P0全局 ExceptionFilter → 统一响应 {code,message,data,traceId}；业务错误码枚举（shared）；pino 日志（按天切割、错误独立文件、traceId 贯穿）任意异常不裸奔 500；日志可按 traceId 追溯
C5decimal 精度P0decimal.js 封装：mul/round2/roundHalfUp；金额数量 DTO 全局序列化为字符串；禁止 number 传入的 lint 规则0.1+0.2 类用例全过；API 出参全是字符串
C6idempotency 幂等P0POST 拦截器：读 Idempotency-Key 头 → 查表 → processing 则返回 1302 / done 则返回原单；事务内写记录连点/重放测试只产生一单
C7audit 审计P0@Audit('piece:approve') 切面：事务内写 before/after JSON + IP；覆盖审核/红冲/改价/重置密码/库存调整/作废六类操作均留痕可查
C8query 查询规范P1统一列表查询构造器：筛选字段白名单（防注入）、排序白名单、分页、全量合计行（SQL 单独 SUM）、Excel 导出（上限 1 万行）排序/筛选字段白名单外被拒
C9notify 通知P1emit(userId, type, title, ref) 接口 + 应用内 emitter 实现（写 notifications 表）；渠道可插拔，后期加公众号 emitter审核结果通知员工闭环
C10print 打印P2hiprint 模板 CRUD（JSON 存库 +version）；按单据数据渲染打印（拣货单/二联/配送单）；PDF 生成（单例 puppeteer，低并发够用）模板在线可改；二联针式打印对齐
C11schedule 定时P2@nestjs/schedule 封装：账期/逾期/发货预警 cron（幂等不重发）；PM2 双实例下用 pg advisory lock 防双跑双实例同时跑仅产生一份预警
C12file 文件P1图片上传（报工照片/产品图）：本地磁盘分目录 + 静态服务；大小/类型校验；预留 S3 适配接口（多租户按企业分桶）3MB 限制生效；路径穿越防护
组件完成定义（DoD）：接口签名 + 单测 + README（一段话用法示例）+ 在沙盒 demo 里被至少一个调用方真实引用。未达 DoD 的组件不阻塞其他泳道（调用方先用第 4 节契约 mock）。

3功能模块（M1-M11）

功能模块 = 业务域。每个模块自持 controller/service/repository 三层，只暴露 service 契约给其他模块。

编号模块优先级职责依赖对外契约（供他模块调用）
M1base 基础数据P0物料（含分类/包装/条码/均价字段维护）、仓库（含员工虚拟仓）、客户（等级/期初欠款）、供应商（账期/期初应付）、员工（标签/本地外地）、期初库存录入入口C1-C7, C12getVirtualWarehouseId(employeeId)；物料/客户/供应商档案查询
M2stock 库存核心P0stock 表 + stock_ledger 流水；moveStock 唯一库存入口（条件更新防负库存、balance_after、行锁）；调拨/调整单；库存总览三视图 + 流水查询C1-C5, C8; M1（物料/仓库档案）moveStock(tx, moves[], bizType, bizNo)；库存查询 getQty(warehouseId, materialId)
M3price 计价引擎P1price_rules 维护；取价优先级（专属>等级>标准）；包装换算（件价×base_qty，过程中不取整）；min_unit/discount 双模式；快照字段生成（price/price_base/price_source）C5; M1（档案）getPrice(customerId, materialId, packageId, bizDate) → 快照对象
M4purchase 采购P1采购入库（含移动加权均价更新，同事务）、采购退货红字（冲库存+冲应付+成本冲回）M2(moveStock), M1; C6,C7采购单查询（应付模块聚合用）
M5sales 销售P1销售订单（包装计价、draft 改价权限+审计、confirm 锁快照、出库成本快照）、拣货执行（事务出库）、销售退货红字、二联单数据组装M2(moveStock), M3(getPrice), M1; C6,C7,C10销售单查询（账单/报表聚合用）
M6process 配送发料P2配送单（多行发料）：确认发料 = 实体仓→员工虚拟仓 moveStock；配送单打印数据M2(moveStock), M1(getVirtualWarehouseId); C10员工仓在制量查询
M7piece 报工计件P2报工单（员工多行自主提交、白名单产品+我的工价、提交前撤回）；审核（行级改数量原因必填、单事务：output_material_id 库存联动 + 计件入账 + 通知）；作废红冲；预提工资与月结结算（单个或批量批次：期间/日期圈选→三层防重复锁定→wage_slip 个人单+wage_settlement_summary 批量汇总清单（列出所有记录）→指定日期确认→红冲回预提）；我的工钱（未发/已发）；计件报表（员工/物料/月矩阵）M2(moveStock), M1; C5,C6,C7,C9,C10, C12计件工钱聚合（毛利报表用）；预提/已结算余额
M8bill 账单P2月度账单生成（幂等；首期并入客户期初欠款）、收款登记（不可超额）、账单查询M5(销售查询), M1; C6,C9应收汇总
M9payable 应付P2供应商付款登记（一付多单核销 payment_refs）、应付报表（期初+采购−付款−退货实时聚合）M4(采购查询), M1; C6应付汇总
M10report 报表P3销售报表（客户/月/物料，退货净额）、毛利报表（销售−出库成本−计件工钱）；全部只读、走各模块契约 service、SQL 聚合M4,M5,M7 契约; C8—（终端消费方）
M11alert 预警P3账期到期前 3 天、逾期 1/7/15 分级、发货超期；alert_records + 通知联动（finance/sales 角色）M5,M8; C9,C11—（终端消费方）
前端对应拆分：PC 端按同样 11 个模块组织路由与页面目录；移动端独立应用仅含 报工/工钱/审核/通知/单据查看 五块，只依赖 M7、C2、C9 与打印查看接口——移动端可与 PC 端完全并行。

4核心契约接口（并行开发的关键）

以下 5 个契约是模块间的全部耦合点。先定签名、再各自开发、最后联调——签名在联调前变更必须通知所有泳道。

4.1 moveStock —— 库存变动唯一入口（M2 提供，M4/M5/M6/M7 消费）

interface StockMove {
  warehouseId: number; materialId: number;
  qtyChange: Decimal;        // 正=入库 负=出库（基础单位数量）
}
// 返回每笔 balance_after；库存不足抛 BizError(1301)，整个事务回滚
moveStock(tx, moves: StockMove[], ctx: {bizType, bizNo, operatorId}): Promise<BalanceAfter[]>

4.2 getPrice —— 计价唯一入口（M3 提供，M5 消费）

getPrice(tx, args: {customerId, materialId, packageId, bizDate}): Promise<{
  price: Decimal;        // 该包装单价（元/袋）
  priceBase: Decimal;    // 参考件价（元/件）
  priceSource: 'exclusive'|'level'|'fallback';
}>
// 折扣模式也在此内完成换算；manual 改价由 sales 模块覆盖并标 source=manual

4.3 getVirtualWarehouseId（M1 提供，M6/M7 消费）

getVirtualWarehouseId(tx, employeeId: number): Promise<number>  // 不存在则同事务创建

4.4 emit —— 通知（C9 提供，M7/M8/M11 消费）

emit(tx, {userId, type, title, content?, refType?, refId?}): Promise<void>

4.5 更新均价 —— 成本入口（M2 提供，M4 消费）

// 采购入库事务内调用：新均价=(旧量×旧均价+入量×采购价)/(旧量+入量)，Decimal 精确
updateAvgCost(tx, {materialId, inQty, inUnitPrice}): Promise<void>
Mock 策略：每个契约在 packages/shared 定义 TS interface + 一个内存 mock 实现。上游未就绪时，下游 import mock 联调页面与流程；上游就绪后换真实 import，业务代码零改动。

7联调顺序与集成策略

  • 契约先行：第 4 节 5 个契约 + shared 包是第一周唯一必须完成的事，之后三泳道立即并行
  • mock → 真实替换：模块开发期用 mock 契约自测页面流程；上游就绪后 jest.mock 换真实 import，跑契约一致性测试（同一组用例对 mock 与真实实现断言相同结果）
  • 集成顺序（每步都是可演示增量）：登录+RBAC → 基础数据+库存 → 采购→销售→打印 → 配送→报工→移动端 → 账单→应付→报表→预警
  • 事务联调专项：审核四联动（库存+计件+通知+审计）、拣货出库、采购均价更新三处必须在集成环境用失败注入验证原子性
  • 分支策略：main 保护；每泳道 feature/* 分支；契约文件（shared）改动走 PR + 双泳道评审

8工程结构与共享包

erp/                                  # pnpm monorepo
├─ apps/
│  ├─ api/                            # NestJS 单体（C1-C12 + M1-M11 各占 src/ 一级目录）
│  │  └─ src/
│  │     ├─ infra/                    # C1-C12 基础组件（auth/rbac/error/decimal/...）
│  │     ├─ modules/                  # M1-M11 功能模块（每模块 controller/service/repository）
│  │     └─ main.ts
│  ├─ pc/                             # Vue3 + Arco（管理端）
│  └─ mobile/                         # Vue3 + Vant（/m H5，Capacitor 套壳出 APP）
├─ packages/
│  └─ shared/                         # ★ 并行开发的锚点
│     ├─ types/                       # 契约 interface（moveStock/getPrice/...）
│     ├─ permissions/                 # 权限码常量 + 角色映射（前后端同源）
│     ├─ error-codes/                 # 错误码枚举与文案
│     └─ mocks/                       # 契约 mock 实现
└─ pnpm-workspace.yaml
  • shared 包是并发开发的核心机制：前后端、三个泳道全部从它 import 类型与常量，杜绝"字段对不上"类联调事故
  • 模块目录边界用 ESLint no-restricted-imports 强制（modules/* 之间禁止深层 import，只允许 index.ts 导出的契约）
  • 数据库迁移只允许从 api 仓库发出（单一迁移源，避免并行改表冲突）；DDL 基准 = v1.3 设计文档第 4 节

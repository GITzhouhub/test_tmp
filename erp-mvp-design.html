仓储进销存 ERP — MVP 详细设计文档

版本 v1.4（补预提工资与月结结算）日期 2026-10-15 形态 单体 NestJS + PG / Vue3 双端多租户 本期不含，代码预留

本文档整合此前所有设计结论，作为 MVP 开发的唯一依据。评审通过后按第 14 节里程碑推进。参考对象：jshERP（单据-流水绑定、进销存口径）、ERPNext（文档生命周期、价格表、Stock Ledger 结余）。

1范围与目标

1.1 业务目标

  • 多仓库进出仓管理（原料 / 半成品 / 成品，员工虚拟仓）
  • 进销存：采购入库、销售出库、四类退货，全部联动库存
  • 加工外发：半成品配送至员工地址加工，完工审核后成品入库
  • 计件工资：员工移动端提交，审核人确认；本地/外地差异工价
  • 客户分级计价：折扣 或 最小单元价格，价格快照
  • 账单与预警：账期预警（分级）、发货预警
  • 成熟打印：拣货单、二联客户单（针式复写）、配送单

1.2 MVP 包含 / 不包含

状态内容
包含认证与账号（管理员建号/初始密码/强制改密/重置）、RBAC 权限、基础数据、库存核心、进销存单据（含全部退货）、拣货+二联+配送打印、加工外发、计件工资、月度账单、账期/发货预警、成本与毛利（移动加权平均 + 出库成本快照 + 毛利报表）、销售报表、客户期初欠款、供应商应付款（赊账/付款/应付报表）、操作审计、移动端员工功能（提交完工/我的工钱）、移动端单据查看
不包含多租户（第 13 节预留）、库位管理（仅记录到仓库级，字段预留）、批次/序列号、自定义报表、字段级权限、盘点（MVP 用调拨盈亏单人工处理）、与电商/财务系统对接、总账/凭证/税务模块

1.3 规模假设

日访问 ≤ 2000，峰值 <10 QPS，用户数 ≤ 100，单据量 ≤ 500/天。所有容量设计基于单机 2C4G。

sales销售订单、拣货、销售退货、二联单

infra审计日志、幂等记录、登录日志

3.1 核心决策：员工 = 虚拟仓库

发料 = 半成品仓 → 员工仓（调拨）；完工审核 = 员工仓 → 成品仓（调拨）+ 生成计件记录。加工链路完全复用库存模型，员工在制数量天然可查（员工仓余额），无独立"在制台账"。

4数据模型（DDL）

以下为核心表完整 DDL（Prisma schema 同构，此处以 SQL 表达精度与约束）。通用约定：主键 BIGSERIAL；软删/停用用 status；乐观锁字段 version INT DEFAULT 1；时间戳 created_at/updated_at。

4.1 认证与账号

CREATE TABLE users (
  id              BIGSERIAL PRIMARY KEY,
  login_name      VARCHAR(50) NOT NULL UNIQUE,
  password_hash   VARCHAR(100) NOT NULL,          -- bcrypt
  display_name    VARCHAR(50) NOT NULL,
  employee_id     BIGINT,                          -- 可空，worker 必填
  status          SMALLINT NOT NULL DEFAULT 1,     -- 1启用 0停用（停用不删）
  must_change_password BOOLEAN NOT NULL DEFAULT TRUE,
  token_version   INT NOT NULL DEFAULT 0,          -- 重置密码 +1 → 旧 token 全失效
  failed_attempts SMALLINT NOT NULL DEFAULT 0,
  locked_until    TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE user_roles (          -- 角色定义写死在代码常量，仅分配关系入库
  user_id BIGINT NOT NULL,
  role_code VARCHAR(30) NOT NULL,  -- super_admin/warehouse/sales/auditor/worker...
  PRIMARY KEY (user_id, role_code)
);

4.2 基础数据

CREATE TABLE employees (

  address VARCHAR(200), remark VARCHAR(500),

CREATE TABLE material_categories (          -- 分类树（学 jshERP）
  id BIGSERIAL PRIMARY KEY, parent_id BIGINT, name VARCHAR(50) NOT NULL, sort INT DEFAULT 0
);
CREATE TABLE materials (
  id BIGSERIAL PRIMARY KEY, code VARCHAR(50) NOT NULL UNIQUE,
  name VARCHAR(100) NOT NULL,
  category_id BIGINT,                       -- 必填：分类
  type VARCHAR(10) NOT NULL,                -- 必填：raw | semi | finished
  unit VARCHAR(10) NOT NULL,                -- 必填：基本单位（件）
  -- ---- 以下全部选填，实际录入可留空 ----
  model VARCHAR(50), spec VARCHAR(100),     -- 型号 / 规格（3寸/孔距96）
  brand VARCHAR(50), color VARCHAR(30), mfrs VARCHAR(50),
  weight NUMERIC(10,3), barcode VARCHAR(50),-- 重量kg / 条码（拣货扫码）
  min_unit_qty NUMERIC(14,3),               -- （废弃，改用 material_packages）
  piece_enabled BOOLEAN NOT NULL DEFAULT FALSE,     -- 启用计件
  output_material_id BIGINT,                -- 加工产出映射（半成品→成品）
  last_purchase_price NUMERIC(14,4),        -- 采购参考价
  avg_cost NUMERIC(14,4) NOT NULL DEFAULT 0,-- 移动加权平均成本（采购入库时更新；期初导入可录）
  image_url VARCHAR(300), ext_props JSONB, remark VARCHAR(500),
  status SMALLINT NOT NULL DEFAULT 1, version INT NOT NULL DEFAULT 1
);
CREATE TABLE material_packages (            -- 包装单元（成品：件/袋/箱）
  id BIGSERIAL PRIMARY KEY,
  material_id BIGINT NOT NULL,
  name VARCHAR(20) NOT NULL,                -- 件(基础) / 袋 / 箱
  base_qty NUMERIC(14,3) NOT NULL CHECK (base_qty > 0),  -- 换算基础单位数量：1袋=100件
  is_default BOOLEAN NOT NULL DEFAULT FALSE,-- 下单默认包装
  status SMALLINT NOT NULL DEFAULT 1,
  UNIQUE(material_id, name)
);
-- 计价双模式：按件价换算（件价×base_qty，四舍五入到最后一步）或直接指定整包价（下单人可改，走改价权限+审计）
-- 必填仅5项：编码/名称/分类/类型/单位；录入页"必填在上、选填折叠"
CREATE TABLE warehouses (
  id BIGSERIAL PRIMARY KEY, code VARCHAR(30) NOT NULL UNIQUE,
  name VARCHAR(50) NOT NULL,
  type VARCHAR(15) NOT NULL,               -- real | employee_virtual
  employee_id BIGINT UNIQUE,               -- 虚拟仓必填且一对一
  -- 选填：keeper(负责人) address remark
  keeper VARCHAR(50), address VARCHAR(200), remark VARCHAR(500),
  status SMALLINT NOT NULL DEFAULT 1
);
CREATE TABLE customers (
  id BIGSERIAL PRIMARY KEY, code VARCHAR(30) NOT NULL UNIQUE,
  name VARCHAR(100) NOT NULL,
  level VARCHAR(2) NOT NULL,               -- A | B | C
  price_mode VARCHAR(10) NOT NULL,         -- discount | min_unit
  discount NUMERIC(5,4),                   -- 如 0.9500（95折）
  credit_days SMALLINT NOT NULL DEFAULT 30,
  opening_balance NUMERIC(14,2) NOT NULL DEFAULT 0,  -- 期初欠款（并入首期账单）
  status SMALLINT NOT NULL DEFAULT 1, version INT NOT NULL DEFAULT 1
);

CREATE TABLE stock (

  PRIMARY KEY (warehouse_id, material_id)

  id BIGSERIAL PRIMARY KEY,

                                   -- purchase_return_out/transfer/process_issue/
                                   -- process_finish/adjust

4.5 进销存单据（以销售为例，采购同构）

CREATE TABLE sales_orders (
  id BIGSERIAL PRIMARY KEY, no VARCHAR(40) NOT NULL UNIQUE,  -- SO20261015001
  customer_id BIGINT NOT NULL, status VARCHAR(15) NOT NULL DEFAULT 'draft',
  total_amount NUMERIC(14,2) NOT NULL DEFAULT 0,
  biz_date DATE NOT NULL DEFAULT current_date,  -- 业务时间（可改限7天内）
  promise_ship_date DATE, remark VARCHAR(500),
  creator_id BIGINT NOT NULL, version INT NOT NULL DEFAULT 1,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE sales_order_items (
  id BIGSERIAL PRIMARY KEY, order_id BIGINT NOT NULL,
  material_id BIGINT NOT NULL,
  package_id  BIGINT NOT NULL,                -- 包装（件/袋/箱），快照 package.name/base_qty
  qty NUMERIC(14,3) NOT NULL CHECK (qty > 0), -- 按包装的下单数量（5袋）
  base_qty NUMERIC(14,3) NOT NULL,            -- 基础单位数量=qty×换算（500件，库存联动用）
  price NUMERIC(14,4) NOT NULL,               -- 单价：按所选包装（元/袋）
  price_base NUMERIC(14,4),                   -- 参考件价（元/件，仅展示，避免混淆）
  discount NUMERIC(5,4),
  amount NUMERIC(14,2) NOT NULL,              -- 总价：round(price*qty,2) 再折（=该行金额）
  cost_unit NUMERIC(14,4),                    -- 出库时成本快照（元/基础单位，=当时 avg_cost）
  cost_amount NUMERIC(14,2) NOT NULL DEFAULT 0, -- 总成本快照 = cost_unit×base_qty（毛利用）
  price_source VARCHAR(15) NOT NULL           -- exclusive|level|fallback|manual(改价)
);
-- 退货 = 红字反向单：sales_returns / purchase_returns 结构同 items，
-- 引用原单行 original_item_id，单价取原行快照，产生反向库存流水。
-- 采购单 purchase_orders 同构（supplier_id 替代 customer_id，增加
--   paid_amount NUMERIC(14,2) DEFAULT 0 / pay_status: unpaid|partial|paid）
CREATE TABLE payment_records (             -- 供应商付款（应付款核销）
  id BIGSERIAL PRIMARY KEY, no VARCHAR(40) NOT NULL UNIQUE,
  supplier_id BIGINT NOT NULL, amount NUMERIC(14,2) NOT NULL,
  method VARCHAR(10) NOT NULL, paid_at DATE NOT NULL,
  operator_id BIGINT NOT NULL, remark VARCHAR(500),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE payment_refs (                -- 付款 ↔ 采购单 核销关系（可一付多单）
  payment_id BIGINT NOT NULL, purchase_order_id BIGINT NOT NULL,
  amount NUMERIC(14,2) NOT NULL, PRIMARY KEY(payment_id, purchase_order_id)
);
-- 应付余额 = 期初 + 采购确认额 − 付款核销额 − 采购退货冲抵（SQL 聚合实时算）
CREATE INDEX idx_po_supplier ON purchase_orders(supplier_id, pay_status);

  unit_price NUMERIC(14,4) NOT NULL,                   -- 提交时点"我的工价"快照

CREATE TABLE wage_settlements (           -- 工资结算单（月结打单确认）

5权限设计

5.1 权限码规范

格式 {模块}:{资源}:{动作}。后端 @RequirePermissions('sales:order:create') + Guard 是唯一准绳；前端路由 meta.permissions + v-permission 指令只控显隐。角色→权限映射写死在代码常量（防库被改），界面只读展示，修改权仅 super_admin（改代码）。

6业务状态机

单据状态流转关键约束
销售订单draft→confirmed→picking→shipped→settled/closed作废仅 draft；出库后修改只能走销售退货红冲；confirmed 时锁价格快照
报工单submitted→approved / rejected；approved 后可 voided审核可改行数量（≤提交数，差异原因必填），单价不可改（提交时点"我的工价"快照）；approved 即锁定；作废=红冲单事务（成品仓−N→员工仓+N→明细行 voided→任务回 submitted），工钱实时聚合自愈；员工提交后审核前可自行撤回重新编辑
工资结算单draft(锁定明细)→settled；settled 后可 voided生成=按期间锁定 approved 未结算明细（写 settlement_id，防重复结算）；打单（wage_slip）→ 指定 settle_date 确认结算；作废=红冲（明细回预提，可重新结算）；draft 期间该批明细不可再入其他结算单；预提余额=SUM(approved 且 settlement_id 为空)
账单confirmed→partial_paid→settledoverdue 由预警 cron 计算，不落库状态；收款累计不可超额
所有单据—不可物理删除，只可作废/红冲；作废权限独立控制并写审计；统一三时间：biz_date（业务时间，可改限7天内）/created_at（录入时间，不可改）/环节时间（submitted_at 等，自动记）
计件数据流：配送单管发料（员工仓在制参考量），报工单管计件（员工自主多行明细，明细行即计件账）；库存联动由 materials.output_material_id 决定：配置则员工仓−半成品/成品仓+成品两笔流水，未配置纯计件不动库存。

7API 设计规范

7.1 统一约定

  • 前缀 /api/v1；REST 动词语义；分页 ?page=1&pageSize=20，响应 {list, total, page, pageSize}
  • 金额/数量 JSON 传输一律字符串：{"amount":"1234.50"}
  • 创建类 POST 必带 Idempotency-Key 头（前端每次提交生成 UUID）；重复键返回原单据
  • 认证：Authorization: Bearer <accessToken>；accessToken 2h 内存持有，refreshToken httpOnly Cookie（APP 端 Capacitor SecureStorage）

8金额与数量精度（强制规范）

层级规则
数据库金额 NUMERIC(14,2) / 单价 NUMERIC(14,4) / 数量 NUMERIC(14,3)；禁 float/double
应用层Prisma Decimal ↔ decimal.js；禁止 JS number 参与金额乘加
API字符串传输；前端仅展示时 format
聚合SUM/GROUP BY 一律 SQL 层完成，禁止 JS 循环累加
取整统一 ROUND_HALF_UP；行金额 = round(round(单价×数量,2)×折扣,2)，只在最终一步取整
包装换算整包单价 = 件价 × 包装换算量（Decimal 精确乘，换算与折扣过程中不取整，仅最终金额取整）；库存一律按基础单位数量 base_qty 联动，包装数量仅展示层
尾差整单折扣分摊：最后一行 = 单据总额 − 已摊行合计
防负库存事务内条件更新：UPDATE stock SET qty=qty-$n WHERE ... AND qty>=$n RETURNING qty，0 行即回滚报 1301

12非功能设计

12.1 错误捕获（不崩溃、可观测）

  • 前端：app.config.errorHandler + 路由错误兜底页 + axios 拦截器统一弹错（按 7.2 错误码映射）
  • 后端：全局 ExceptionFilter → 统一结构 + traceId；pino 按天切割，错误单独文件；每日巡检错误日志（不引入 Sentry）
  • 事务边界：所有多表写操作在 service 层单事务，任一步失败整体回滚（如"半审核"不可能存在）

12.2 防重复提交

  • 前端：按钮 loading 锁定；每次提交生成 UUID 幂等键
  • 后端：idempotency_records 表（key 主键）——重复键返回原单据；数据库唯一约束兜底
  • 弱网：GET 自动重试 1 次；POST 失败移动端存草稿同键重试

12.3 安全

  • bcrypt(cost≥10)；初始密码 = 6 位数字（管理员建号/重置时下发）；用户自设密码 ≥8 位，不限纯数字或纯字母（无复杂度强制）；首登强制改密（未改完拦截所有业务接口）
  • 重置密码 → token_version+1 → 旧 token 全失效；登录失败 5 次锁 15 分钟；登录限流
  • 密钥只在后端 .env（git 忽略 + example 模板）；前端零密钥
  • 审计日志覆盖：计件审核、红冲、改价、重置密码、库存调整、作废（before/after JSON）

12.4 备份

pg_dump 每日全量，保留 7 天滚动 + 每月一份留 30 天；每季度恢复演练到临时库验证。

  • 业务表零 tenant_id 字段、零跨库假设 SQL
  • 上传文件按 uploads/{企业代号}/ 目录分桶（MVP 就用固定代号）
